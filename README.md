# Pocket Arcana

**Standalone Godot project. Never place this inside Pixel Ranch.**

Pocket Arcana is a 2D pixel-art living-board collectible card game: easy to understand at a glance, deep enough to support serious deckbuilding. Players shape an elemental world, summon creatures and landmarks into real board positions, mix elemental states into discovered terrain, protect or break persistent Hearts, and decide when to pass to preserve cards across a best-of-three Chapter match.

## Current build package
- Godot 4.7.2 graybox project with `project.godot` + runnable `scenes/main.tscn` target
- 7×5 living board simulation
- best-of-three Chapter / pass model
- persistent 25-point Heart, 10-Wonder alternate victory, Chapter Seals
- 8 elements: Frost, Lightning, Life, Fire, Water, Earth, Wind, Death
- 240-card design pool (32 marked slice-ready)
- 24 Commanders (3 per element)
- 8 legal 40-card starter decks
- 28 two-element terrain recipes
- 12 tokens
- deterministic simple AI shell
- mouse-driven graybox UI generated by `scripts/ui/main.gd`
- content validator + audit tools

## Running it

```bash
GODOT=~/godot-editor/Godot.app/Contents/MacOS/Godot
"$GODOT" --path .                     # play a match
./tools_verify.sh                     # every check, one command
./tools_verify.sh --balance           # plus 200 matches per seating (slow)
```

## Checks

| command | what it proves |
| --- | --- |
| `python3 tools_validate_content.py` | content is structurally legal and the slice invariants hold |
| `python3 tools_content_audit.py` | element/type/rarity distribution and card-text length |
| `./tools_check_scripts.sh` | every `.gd` parses under the real Godot binary |
| `scenes/dev/tests.tscn` | 82-check simulation regression suite |
| `./run_smoke_test.sh` | an AI-vs-AI match finishes |
| `scenes/dev/ui_playthrough.tscn` | a full match survives the real UI click handlers |
| `scenes/dev/balance.tscn` | win rates, win reasons and match length over many seeds |
| `scenes/dev/screenshot.tscn` | captures a named gameplay scenario to a PNG |

Screenshot a specific state:

```bash
"$GODOT" --path . --scene res://scenes/dev/screenshot.tscn -- \
    --out=/tmp/shot.png --scenario=heart_strike
```

Scenarios: `opening`, `card_selected`, `shape_selected`, `midgame`,
`unit_selected`, `heart_strike`, `ashbloom`, `chapter_overlay`, `match_end`, `help`.

## Where the vertical slice stands

Life vs Fire is playable end to end: 7x5 living board, Chapters and Passing,
Attunement, the Ashbloom recipe, explicit Heart strikes against the Sanctuary
Ward, Commander passives and Commands, a Pass preview, Chapter and match
overlays, and a first-match coach built from `data/tutorial_steps.json`.

Over 200 matches per seating the two starters sit at Life 54.5% / Fire 45.5%,
and they win differently: Life takes ~80% of its wins on Chapter Seals, Fire
~60% of its wins by breaking the Heart.

`docs/IMPLEMENTATION_NOTES.md` for why the rules were tuned the way they were.
